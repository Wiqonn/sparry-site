Explore the security controls

Your own sandbox

Create an isolated execution environment for your agents. Define the shared workspace, file access and network boundaries.

Sandbox isolation is optional. Direct local mode uses your host permissions. Mounts and network settings define the sandbox boundary.

Action confirmation

Require confirmation before Sparry's built-in agents execute actions. With an LLM risk analyzer, confirmation can focus on high-risk actions.

Enabled through the confirmation policy. External providers have their own controls.

Prompt injection defenses

Check tool actions for known injection patterns and suspicious commands before they run. Configure risk analysis together with action confirmation.

Pattern, LLM and policy analyzers are available for Sparry's built-in agents. Detection has limits; combine it with isolation and human review.

Scoped source access

Sparry's source reader supports read-only SQL, bounded results and named secrets outside connection URLs.

Use SELECT-only database accounts. The source reader's restrictions do not apply to terminal tools.

Named credentials

Keep source credentials in named secrets rather than embedding them in connection URLs.

Credential handling depends on the connector and runtime. Give each integration only the access it needs.
